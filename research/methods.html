Methods

How every number on this site is produced, so that a reviewer can repeat it.

Data acquisition

The sandbox network allow-list permits GitHub and PyPI hosts only, so bulk inputs are pulled from GitHub through the REST contents API and cached under data/raw. Every file is recorded with its byte size and SHA-256 in data/raw_manifest.json, so a reviewer can confirm that a published table came from a specific file. League-operated pages (NFL injury reports, the season calendar, the rule book) are cited directly and transcribed where the values are published row by row.

Walk-forward evaluation

For every evaluation season, each strategy's parameters are re-selected using only games that finished in earlier seasons, then applied to the evaluation season. Parameters are chosen by a risk-adjusted score (mean profit divided by its standard error) so that a high return on a handful of bets cannot beat a steadier signal with more evidence. The evaluation window runs from 2015 to the 2026 season, which gives every strategy thousands of out-of-sample bets and every parameter choice a genuine test.

Originated lines

A Poisson points model is fitted on stacked team-game rows: points ~ C(team) + C(opponent) + elo_diff + rest_diff + is_home. Team dummies give attack and defence ratings, the pre-game Elo difference adds a dynamic strength signal, rest difference captures scheduling, and the home indicator captures the scoring level. The model is refitted for every season using only earlier seasons, so no game is scored by a model that has seen it. The originated spread is the difference between the two predicted point totals and the originated total is their sum, both rounded to half points.

Validation gates

Eight gates, applied identically to every strategy: sample sufficiency, out-of-sample integrity, statistical significance (bootstrap interval plus a sign-flip randomisation test), economic significance, superiority over naive baselines, luck robustness, parameter stability and non-redundancy. A strategy that fails any gate earns no reward and is published with the measured values that caused the failure.

Removing luck

One-score games (margin of 8 points or fewer) and blowouts (25 points or more) are removed and the strategy is re-scored (gate G6). Turnover luck and drive-level variance are not yet controllable because play-by-play data is not in the pipeline - that is question Q12.

Correlation and parlay arithmetic

Strategy correlations are Pearson correlations of per-bet profit streams over shared games. For parlays, a two-leg combination at -110 needs a 27.5% joint hit rate; the joint probability is computed from each leg's hit rate and the correlation between the legs (p1*p2 + rho*p1*(1-p2)), which is what makes the prop-combo table a decision tool rather than a list of numbers.

Reward formula

reward = 1000 * ROI * min(1, bets / 300) * confidence, where confidence is the share of the bootstrap confidence interval that stays above zero. Rejected strategies earn zero.

What is not modelled yet

  • Drive-level efficiency (EPA, success rate, third-down rate) - needs play-by-play (Q1, SG3).
  • Closing-line value - needs opening and closing prices stored per game (SG5).
  • Player-prop pricing - needs a market prop feed (Q9).
  • Turnover luck - needs play-by-play (Q12).
  • Multi-season injury adjustments - needs a multi-year injury feed (Q8).
