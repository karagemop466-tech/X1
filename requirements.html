Requirements

The full, organized list of requirements the system must satisfy. Requirements are grouped by category and carry a priority. Items marked Source-bound must be satisfied using an official/authoritative source; see the Sources index.

Critical — blocks the system Important — required for full function Source-bound — must use official source

A. Data collection

A-01Collect official standings Source-boundPull full W/L/T, PCT, PF/PA, Net Pts, Home/Road/Div/Conf/Non-Conf, streak for all 32 teams from an official league source.Critical
A-02Collect official injury reports Source-boundPull the league and per-team injury report: player, position, injury, practice status, and game status (Out / Doubtful / Questionable / Active).Critical
A-03Collect market betting lines Source-boundPull opening and current point spread, moneyline, and total for each game from an authoritative sportsbook/aggregator feed to serve as the market benchmark.Critical
A-04Collect play-by-play & EPA Source-boundPull play-by-play and per-play Expected Points Added (EPA) for offense and defense — the core skill signal for model-generated lines.Critical
A-05Collect depth charts & rosters Source-boundPull official depth charts and rosters to determine starter vs. backup (2nd/3rd/4th string) order for offense and defense.Important
A-06Collect player-prop lines Source-boundPull per-player prop lines (passing/receiving/rushing yards, TDs, etc.) from an authoritative sportsbook feed.Important
A-07Collect historical results Source-boundPull historical game results and closing lines to compute out-of-sample performance and correlation over prior seasons.Critical
A-08No manual data entry The pipeline runs end-to-end without manual input; data is fetched, verified, and stored automatically.Critical

B. Data organization

B-01Structured, versioned storageStore every dataset in a structured, versioned format (e.g., JSON) with fetch timestamp and source metadata attached.Critical
B-02Source link per recordSource-boundEvery stored record carries the URL of the official source it came from, so any value is auditable end-to-end.Critical
B-03Point-in-time snapshotsStore snapshots with a timestamp so injuries and lines can be referenced as of a specific week (lines and statuses change).Important
B-04Schema normalizationNormalize team names, abbreviations, positions, and status enums to a single controlled vocabulary across all feeds.Important

C. Analysis

C-01Luck-adjusted team strengthCompute luck-adjusted measures (net points, EPA differential, Pythagorean-style expectation) instead of relying on raw win-loss.Critical
C-02Injury/depth impact analysisQuantify how starter absences (and 2nd/3rd/4th-string substitutions) shift expected performance and line movement, by unit and position.Critical
C-03Signal extractionConvert raw data into directional signals (against-spread, moneyline, total, prop) with an associated confidence/edge value.Critical
C-04Correlation estimationEstimate pairwise correlation between bet legs (team performance, player props, game totals) from historical data.Important

D. Line generation (our own lines)

D-01Originate our own linesGenerate our own point spreads, moneylines, and totals from the model — independently of the market — for every game.Critical
D-02Compare to market (CLV)Compare our lines to the closing market line to compute Closing Line Value (CLV) — the primary skill signal.Critical
D-03Generate prop linesOriginate our own player-prop lines (e.g., player passing/receiving/rushing totals) from the model.Important
D-04No fabricated linesPublish only computed lines; never infer or fill in a line that the model has not produced.Critical

E. Strategy & leaderboard competition

E-01Single-bet strategiesSupport straight point-spread / moneyline / total strategies with EV and edge per bet.Critical
E-02Parlay strategiesSupport parlay construction with correlation-aware true probability, not the book's independence assumption.Critical
E-03Player-prop combo strategiesSupport combined player-prop bets (e.g., QB + WR stacks) with correlation between legs.Important
E-04Leaderboard with rewardsRank strategies by a validated metric and award top performers; only strategies passing all gates qualify.Critical
E-05Skill over luckRank by luck-adjusted, statistically significant performance; remove luck from the ranking.Critical

F. Validation gates

F-01Every strategy passes gatesNo strategy is admitted to the leaderboard or receives rewards until it passes every validation gate.Critical
F-02Out-of-sample / walk-forwardValidate on out-of-sample, walk-forward periods with no look-ahead bias.Critical
F-03Statistical significanceRequire edge significance (confidence interval excludes zero) before a strategy is considered skill.Critical
F-04ReproducibilityPin data and code versions so every validated result is reproducible.Important

G. Injury & depth tracking

G-01Track injuries by player & unitTrack injuries with player, position, unit (offense/defense/special teams), practice status, and game status.Critical
G-02Starter/backup string trackingTrack starter vs. 2nd/3rd/4th-string substitutions for offense and defense; flag units forced to play backups.Critical
G-03Deficiency → signalTranslate backup-forced units into a measurable performance/line signal rather than a binary flag.Important

H. Site & UX

H-01Clean dashboard UIA simple, user-friendly dashboard: landing page plus subpages organized by category.Critical
H-02Table-driven presentationPresent all entries and findings in simple, readable tables.Critical
H-03Dedicated suggestions sectionA dedicated, reviewable suggestions section so a decision-maker can choose the best path before implementation.Critical
H-04Flagged-for-review pageA clearly labeled page listing every unverified / irregular item with source links.Critical
H-05Live GitHub Pages sitePublish a live site via GitHub Pages with no broken links.Critical

I. Verification & integrity

I-01Source link on every rowSource-boundEvery data-table row carries a link to an official source.Critical
I-02Blank & flag, never inferIf a value cannot be confirmed from an official source, leave it blank and flag it — never infer or fill it in.Critical
I-03No hallucinationsNo value, link, or claim is published that was not checked against an official source.Critical
I-04Broken-link checkBefore publishing, confirm the site builds and contains no broken internal links.Critical

J. Automation & coordination

J-01Autonomous pipelineThe full pipeline (fetch → verify → organize → analyze → validate → publish) runs without manual input.Critical
J-02Coordination task boardA shared COORDINATION.md task board tracks each task, status, owner, scope, sources, and verification log for parallel sessions.Important
J-03Non-overlapping scopesEach session edits only files in its claimed scope; cross-scope changes are logged, not applied.Important
