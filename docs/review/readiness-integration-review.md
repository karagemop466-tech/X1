## Checks performed

GitHub's Pages API reports `status=built`, `build_type=legacy`, `source=main:/`; the `pages build and deployment` run for commit `3521c43` succeeded ([run 43746751798](https://github.com/karagemop466-tech/X1/actions/runs/43746751798)). 2. **Table arithmetic:** the merged `index.html` table contains 53 rows (R-01 through R-53): 41 `met`, 7 `partly`, 3 `in progress`, and 2 `open`. The same page's summary card says “42 met, 7 partly met, 2 open,” which totals only 51 and omits the three in-progress rows. This is an internal count mismatch, not an NFL fact.
3. **Source labels:** all 53 table rows label their link “official ↗”, but those links point to GitHub repository files (for example, `pages/requirements.html` and `docs/methodology/validation-gates.md`), not official NFL pages. Because these are project-requirement rows, a repository-evidence label is appropriate; “official” should be reserved for the official NFL/club source used to verify an NFL fact. See [the live requirement table](https://karagemop466-tech.github.io/X1/?v=3521c43) and [the official NFL injury report](https://www.nfl.com/injuries/) for the distinction.
4. **Custom workflow versus live Pages source:** `.github/workflows/pages.yml` copies `index.html` and later overwrites `_site/index.html` with `console/index.html`; GitHub Pages is currently configured as `legacy` from `main:/`, so it serves the root `index.html` instead. These are two different deployment trees. The custom `Publish static site to GitHub Pages` run for commit `3521c43` failed at “Crawl the assembled tree for broken links” and skipped its deploy job ([run 43746752096](https://github.com/karagemop466-tech/X1/actions/runs/43746752096)). Re-running `python3 tools/verify_deployed_tree.py` on the current tree reproduces exactly one failure: `legacy-fourth-down.html → docs/methodology/validation-gates.md`; `docs/` is not copied into the custom artifact. The live legacy site currently resolves the same path, but switching to the custom artifact without correcting the assembly would publish a broken legacy page and a different landing page.

Keep one canonical register and rebase/recompute it against current `main` before merging any duplicate.
