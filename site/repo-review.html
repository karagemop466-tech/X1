Repository review, file by file

Every tracked file, hashed and line counted, run through a fixed set of mechanical review rules. Each row links to the file on GitHub so you can open it and check the finding yourself.

The review is generated, not written by hand. The rules are mechanical — empty file, missing trailing newline, TODO or FIXME markers, placeholder values, hardcoded-secret shapes, bare except:, debug prints, oversized files and lines, and unclosed HTML. Anything needing judgement is on the Flagged for Review page instead of being guessed at. Reproduce it with python3 -m pipeline.repo_review.

Mechanical findings are mostly intentional

Debug print() calls flagged in the pipeline modules are the pipeline's own console output, which is how a scheduled job reports. Bare except: blocks in the parsers are deliberate: a scheduled collector must not crash the run because one page changed. These are visible rather than suppressed so they can be reviewed.

No secrets were found

The hardcoded-secret rule found no credentials in any tracked file. The GitHub token used for git and gh is provided by the environment and is not stored in the repository.
