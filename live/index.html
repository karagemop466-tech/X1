What this system is

X1 collects NFL data from official sources only, tracks injuries and the backup players who have to replace injured starters, originates its own lines, and scores candidate strategies on a leaderboard behind a set of validation gates. It runs unattended: a scheduled workflow re-pulls every official source, re-verifies every row, and republishes this site.

What is verified today

  • Standings — all 32 clubs, every row checked against the league's own arithmetic.
  • Injuries — the league's official injury report, re-pulled on a schedule.
  • Depth charts — starters through 4th string, from each club's own site.
  • Team stats — nine official offensive and defensive tables with their printed column labels.
  • Correlations — computed from those official numbers, with n and p printed next to every value.
  • Deficiency watch — which starter is out and which string of backup has to replace them.

What is deliberately blank

  • Market lines — no official source publishes betting prices, so the table ships empty.
  • Leaderboard results — no official source publishes game results in a machine-readable form, so no strategy has a graded record.
  • Player prop data — no official prop-level source was verified.
  • Weather, officials, and rest/travel — no citable source found, so no values are shown.

These are not oversights. The verification rule is that a value which cannot be confirmed from an official source stays blank and is flagged, never inferred.

Headline findings

  1. The repository started empty. At the beginning of this session the repo contained one file, a 4-byte README.md. Everything on this site was built in this session. Source: initial commit ↗
  2. Official data is machine-readable without a licence. Standings ↗, injury reports ↗ and team stats ↗ are server-rendered, so the pipeline reads them with the Python standard library and no API key.
  3. Standings pass their own consistency check. For all 32 clubs, home record plus road record equals the overall record, and points for minus points against equals net points. The check runs on every refresh and is reported on the standings page.
  4. Backups replacing starters are identifiable from official data. Cross-referencing each club's printed depth chart with the league's injury report gives the exact string of the next available player. See the deficiency watch.
  5. Not every official club site is reachable. Some club depth charts fail to return a parsable page. Those clubs are listed with their HTTP attempt log on the Flagged for Review page rather than being guessed at.
  6. Correlations can be computed now, at team level. Example: offensive total touchdowns against points for, r = 0.94 with n = 32, from official scoring stats ↗ and official standings ↗. These are team-level associations and are not the same quantity as the same-game correlation a parlay price needs.
  7. Two inputs block most of the model. Prices and results. Neither has an official public source, so every gate that depends on outcomes is unenforced rather than filled with a guess. See open questions Q-02 and Q-04.

Decision gate — read this before approving anything

The brief asks for the questions that must be answered before a decision is reasonable, and for the missing information to be surfaced. Six questions are hard blockers: they cannot be answered from any official source and they stop specific parts of the system from working.

  • Q-02 — where do market prices come from? Blocks closing line value, parlay pricing and prop pricing.
  • Q-04 — where do verified results come from? Blocks every backtest, ROI figure and skill test.
  • Q-05 — paper or real money? Blocks rewards and compliance.
  • Q-06 — how are rewards defined? Blocks the leaderboard reward rule.
  • Q-01 — what is the bankroll? Blocks staking and leaderboard scoring.
  • Q-11 — is there a player-prop source? Blocks prop combos.

How the verification rule is enforced

On every row

  • Each row carries the URL of the official page the values were read from.
  • A value the source does not publish renders as an em dash, not a guess.
  • A row with any missing value or any integrity flag is marked flag and appears on Flagged for Review.

On every refresh

  • scripts/verify_data.py re-checks every dataset: no row may cite a host that is not on the official list.
  • A pull that returns zero rows never overwrites good data.
  • The run report and the attempt logs are committed to the repo, so the whole history is auditable.
