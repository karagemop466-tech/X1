Irregularities in the brief or the build

Items where the project brief asks for something that the environment, the data, or the verification rule does not allow as written.

F-01 · Branch naming: session-<id>/<task>

The brief asks each session to work on its own branch named session-<id>/<task>. This session is pinned to a single branch by the harness and cannot create or switch to another. Mitigation: the task board ↗ records the owning session and the exact file scope for every task, and the branch is pushed after every small commit, which covers the same conflict-avoidance purpose. Requires an owner decision to close.

Source: project brief, PARALLEL SESSIONS ↗

F-02 · No official source for betting prices

No NFL or club page publishes spreads, totals, moneylines or player-prop prices. The market lines table ships empty rather than populated from memory. Every claim on this site that depends on a price is marked blocked.

Source: nfl.com ↗ and the probe report on the questions page.

F-03 · No official machine-readable results

The league's schedule and score pages return no server-rendered table, so there is no citable source for game results. Backtests, ROI and skill tests are all uncomputable, and the leaderboard result columns stay blank.

Source: nfl.com/schedules ↗, nfl.com/scores ↗.

F-04 · Some official club sites do not return a parsable depth chart

Some clubs' depth chart pages return a non-depth-chart page, an empty body, or refuse the connection. Those clubs are absent from the deficiency watch for that refresh and are listed with their HTTP attempt log on the depth charts page. They are not backfilled from an unofficial source.

F-05 · 2026 standings page prints no column header row

The current standings table has no text header, so four column meanings (Div %, Conf %, Non-Conf, Last 5) are positional. Their order is validated by the arithmetic consistency check rather than by a printed label, and the officially labelled 2025 page ↗ shows the same order. Flagged rather than assumed.

F-06 · Rewards rule is undefined

The brief requires rewards for top performing strategies but does not define them. No reward rule has been invented. Blocked on Q-06.
