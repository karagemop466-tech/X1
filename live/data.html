The verification rules

  1. One official link per row. Every row ends with a link to the page its values came from. A row with no link cannot be rendered.
  2. Blank means the source left it blank. A value the official page does not publish is stored as null and rendered as an em dash. It is never replaced with an estimate.
  3. Hosts are allow-listed. scripts/verify_data.py checks that every _source_url points at nfl.com or at a club domain the league itself lists. Anything else is a hard failure.
  4. An empty pull never overwrites good data. If a refresh returns zero rows for a dataset that previously had rows, the previous data is kept and the incident is logged.
  5. Arithmetic is checked where arithmetic exists. The standings table is validated against the league's own relationships, and the result is printed on the standings page.
  6. The evidence for an absence is published too. When this project says "no official source exists", the probe table on the questions page shows the URL, the HTTP status and the number of tables found.

Refresh schedule

A scheduled job re-runs the whole pipeline with no manual input: it re-pulls every official source, re-verifies every row, commits any change, and republishes this site. The cadence is every six hours, with an extra pass on game days, chosen to match how often the league updates its injury report.

Run it by hand at any time from the Actions tab, or reproduce it locally with python3 -m pipeline.
