Analysis of the requirement set

Where the requirements cluster

  • Verification (8 rows) — the largest single group. The brief returns to official sourcing, blank-not-guessed values and no inference more than to anything else.
  • Coordination (11 rows) — the parallel-session rules are detailed and mostly mechanical, so they were implemented as a task board plus pipeline behaviour rather than as prose.
  • Model (8 rows) — originate lines, signals, leaderboard, rewards, gates, correlation, skill.
  • Site (5 rows), Operations (1), Delivery (5).

Conflicts and gaps found

  • R-33 conflicts with the harness. The brief asks each session to work on a branch named session-<id>/<task>, but this session is pinned to a single branch. Logged as irregularity F-01; the task board records file scopes instead.
  • R-10 (rewards) has no rule to build against. The brief requires rewards but does not say what they are. Blocked on Q-06.
  • R-07 (originate our own lines) depends on market prices that no official source publishes. The model side is built; the comparison side is blocked on Q-02.
  • R-13 (correlation values) is only partly satisfiable. Team-level correlations are computed from official data; game-level and player-level correlation have no verified source.
