Re-verification procedure

  1. Open the row's source link.
  2. Confirm the entity, then the value.
  3. If the official page prints nothing, the cell must be blank. A filled cell with no printed source is a defect — raise a flag.
  4. If the official page disagrees with our row, the page wins and the row is corrected with a note.
  5. For derived rows, re-run python3 tools/build_availability.py and confirm identical output.
  6. For any table, run python3 tools/verify_data.py; it must print all integrity checks passed.

What verification does not prove

An integrity suite catches arithmetic and join errors. It cannot catch a plausible wrong number typed from the wrong row. One such error was caught here only because the arithmetic happened to break (F-08). The remaining defence is a second independent transcription pass, which is suggestion S-10 and has not been done.
